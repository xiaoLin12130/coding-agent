# M12 — Real-Environment Hardening (what the library-system test exposed)

## 背景

用 DeepSeek 网页端（deepseek-web profile）从 Web UI 驱动 coding agent 开发一个
真实的小项目（图书管理系统），过程中暴露的问题与修复记录。

## 修复的问题（均有测试）

| # | 问题 | 后果 | 修复 |
|---|---|---|---|
| 1 | ask 走了一条固定预算的独立轮询 | 每个问题都要等满 180 秒 | 复用 `wait_until_complete` 的完成判定同时上报增量 |
| 2 | Playwright 会话绑定在第一个工作线程 | 第二次运行崩溃：cannot switch to a different thread | 单一 browser 线程 + 全部调用 marshalling，失败尝试一次恢复 |
| 3 | ConsoleModel 用非重入锁自锁 | model() 死锁（控制台卡住） | 改 RLock |
| 4 | 模型回复既发 delta 又发 model_reply | UI 里答案出现两遍 | ask 路径不发 model_reply |
| 5 | clipboard 写入未 await | 粘贴为空 → 回退逐字输入 4800 字（数分钟/步） | await + 校验 + 重试一次，长文本回退 fill |
| 6 | 答案里混入页面 chrome（python / 复制 / 下载） | 模型文本被污染，工具调用解析失败 | profile `ignore_selectors` 读取时剔除 |
| 7 | **代码块缩进被 innerText 折叠** | 生成的 Python 缩进变成 1 空格，文件无法 import | profile `code_block_selector`，代码块用 textContent 精确读取 |
| 8 | run_shell 超时在 Windows 失效 | 子进程持有管道 → 调用永不返回，整轮卡死 | Popen + 杀进程树（taskkill /T） |
| 9 | 两个进程共用浏览器 profile | 启动失败且报错难懂 | 明确报错说明 profile 被占用 |
| 10 | 重复调用直接结束运行 | 模型没有机会纠正 | 结束前注入一次 LOOP WARNING |
| 11 | 控制台默认步数 25 太小 | 真实项目做到一半就没步数 | 默认 40 |
| 12 | 上下文塞入完整 5KB 文件写入 | 每步都触发轮转，模型丢失上一步结果 | transcript 每条裁剪到 1200 字符 |

## 仍然存在的问题（如实记录）

1. 网页端模型在大块结构化编辑上不可靠：连续两次输出非法 JSON（括号不匹配），
   直接导致运行以 error 结束；也会重复同一条命令。
2. 上下文预算 28,000 字符对真实项目偏小，仍会出现每步轮转。
3. 本次生成的图书管理系统**没有完成**：db.py 已可导入，但 tests/test_api.py 因
   app.py 在 import 时调用 main() 而阻塞；agent 未能修复。
4. 当前模型不支持图像输入，截图无法人工核对。

## 结论

系统骨架（解析→安全→执行→循环→控制台）在真实网页端模型上跑通了：回答能流式
回传，工具调用能真实执行，生成的代码在修复缩进问题后可以正常导入。但"独立完成
一个项目"目前受限于模型本身的输出质量与网页端的不稳定性，而不是执行链。
